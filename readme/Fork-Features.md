# Bettbox Smart 使用与升级

使用前请阅读个人自用与责任声明。[README](../README.md)

本 fork 当前聚焦维护 **Smart 策略组**、**连接关闭高 CPU / 内存与资源泄漏稳定性修复**（见 [修复记录](Smart-CPU-Fix.md)）、**Android 端自定义应用名称与展示图标**，以及覆盖本仓库测试版与正式版的应用内更新检查。下文的节点库、落地代理（链式代理）与聚合订阅均已由 Bettbox 上游原生提供，本文保留其使用要点及从旧版 fork 升级的迁移步骤。

## Smart 策略组

导入包含 `type: smart` 的配置，或在配置编辑器中添加 Smart 组。已有的策略组会保留原类型。Smart 会根据目标和连接表现选节点。点击组内节点可固定选择，再点一次恢复自动选择。模型可在「资源 → LightGBM → 同步」更新。[Smart 配置和测速说明](Smart.md)

## 自定义应用名称与展示图标（仅 Android）

在「应用设置 → 自定义应用名称与图标」中可进行个性化伪装（Windows / Linux 端不提供此入口）：

- **直接编辑预览**：点击图标可从相册上传图片（自动裁切为正方形 PNG），点击名称可直接重命名，点击卡片右上角「恢复默认」可一键还原。自定义名称与图标同步生效于应用内标题/关于页、Android 最近任务卡片、前台通知标题与快捷设置磁贴。
- **添加到桌面**：支持以 **小组件 1×1**（无右下角系统角标，修改名称或换图后自动刷新）或 **快捷方式** 两种方式添加到手机/平板桌面。
- **应用抽屉图标**：可在内置的默认、笔记、计算器、实用工具预设之间切换系统应用抽屉入口。

## 节点与落地代理（上游原生）

1. 在「配置」页先选中要使用的配置，再点右上角的「节点」按钮切换到节点页。
2. 点「添加节点」，从剪贴板、文件或手动输入导入单个或多个节点。支持分享链接或 Mihomo YAML 节点等格式，导入的节点库节点会自动排在选择策略组前部。
3. 将「节点用途」设为「落地节点」。普通配置开启「注入到此配置」，选择「前置代理」及要加入的策略组。托管配置启用「应用到托管配置」，从托管地区组选择前置，并检查所选策略组。这项绑定会对所有托管配置生效。
4. 保存后到「代理」页打开所选策略组，选中落地节点，再实际测试连接。流量依次经过前置代理和落地节点。请在切换配置或订阅更新后确认前置仍存在。上游实现遇到前置名称无法解析时会省略 `dialer-proxy`，因此单看节点可选或测速成功不足以确认走了预期路径。

节点库在生成运行配置时注入节点和组成员，原订阅文件保留原样。原生界面为每个绑定选择一个前置，普通配置可从当前已加载的代理组选择前置组或组内节点。多跳顺序和已有 `dialer-proxy` 引用可保留在自管 YAML 中。UDP 是否可用取决于前置、落地协议及服务端，请单独测试。

## 聚合订阅（上游原生）

1. 先在「配置」页导入至少两个普通配置，然后打开「添加配置 → 订阅合并」。入口按已有非聚合配置数量启用。成员可从已有普通配置中选择，也可用「订阅链接」导入新成员。
2. 设置合并订阅名称，按需为成员设置节点前缀，然后点「生成」。新配置会出现在配置列表中，选择它后检查分流和节点。
3. 在合并配置的编辑页可调整成员、前缀或重新生成。成员仍保有各自的订阅来源。成员配置更新后会触发重新生成，手动重新生成也会尝试刷新 URL 成员。检查生成结果和成员失败提示。

生成时先用内置托管脚本处理成员，然后合并节点、按配置内容去重、合并同名策略组成员。首个成功处理的成员提供基础配置。请以生成后的规则和可用组为准，尤其要确认自定义分流设置。聚合配置不能作为另一个聚合配置的成员。

## 从旧版升级

1. **升级前留存材料。** 在旧版的「备份与恢复 → 本地 → 备份」保存应用备份。打开旧版已有链路的编辑页，对需保留的链路分别点「导出生成配置 YAML」，将文件另存。另行记录前置与落地顺序、规则引用、原订阅链接、手动节点参数和额外 Provider。备份和导出可能含凭据，请在本地妥善保存。只有旧备份或链路库 JSON 时，先用兼容的旧版在单独环境恢复并尝试导出。
2. **保留旧链路的实际配置。** 在新版通过「配置 → 添加配置 → 本地文件」导入单独导出的 YAML。测试导入的配置时，先在配置编辑页关闭「托管模式」，并停用会改写这份配置的脚本。检查 `proxies` 中的 `dialer-proxy`、`proxy-groups`、`rules` 及 Provider。按需更新资源并重新选择策略组。导出的内置节点是当时的快照，HTTP Provider 仍按其配置更新。若只有写过旧链路的来源 YAML，也可先复制为本地文件再导入测试，避免直接刷新订阅覆盖修改。
3. **改用原生界面时手动重建。** 常用两段式路线可按上文重新添加落地节点、选定前置，再绑定代理组。旧版只存在于链路库里的定义和外部节点需要从导出的 YAML 或自己的记录取回。原订阅与额外订阅可分别导入后按需聚合。已经写在 YAML 里的手动节点和 Provider 可先从文件恢复，再检查原订阅重新同步后的内容。
4. **逐条验收后再停用旧配置。** 在新版的「备份与恢复 → 本地 → 恢复」可选择「仅恢复配置文件」或「恢复所有数据」。旧链路库 JSON 和旧节点补充记录请留作旧版恢复材料，落地绑定与聚合成员按上述步骤重建。启动并确认每条需要保留的路线、规则匹配、实际出口和所需 UDP 流量，确认恢复成功后再停用旧版或旧配置。
