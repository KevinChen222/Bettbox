# 本 fork 特有功能使用说明

本文介绍 Bettbox Smart 个人 fork 的 Smart 特性，以及如何在界面中手动创建链式代理、添加外部节点。使用前请先阅读 [README 中的个人自用与责任声明](../README.md)。

## Smart（简述）

Smart 策略组会根据目标和连接表现自动选择节点。导入包含 `type: smart` 的配置，或在配置编辑器中添加 Smart 组即可使用；已有策略组不会自动转换为 Smart。

在代理页面点击 Smart 组内的节点可以固定选择，再点击已固定的节点恢复自动选择。资源页面的 **LightGBM → 同步** 可下载或更新模型。配置示例、模型参数和测速行为见 [Smart 使用说明](Smart.md)。

## 手动创建链式代理

链路按 **客户端 → 第一跳（前置）→ 后续跳 → 最后一跳（落地 / 出口）→ 目标** 排列。例如「香港组 → 德国节点」表示先经香港组当前选择的节点，连接德国节点，再由德国节点访问目标。

### 1. 创建一条两跳链路

1. 先在「配置」页面导入需要使用的配置。若节点来自 Provider，先在资源页面同步所需的 Provider。
2. 打开 **工具页面 →「设置」区域 → 代理链路**，点击 **创建链路**，选择要绑定的配置。也可以在工具页面搜索「代理链路」进入。
3. 填写「链路名称」，例如 `香港 → 德国`。
4. 点击 **添加一跳**，选择前置节点或策略组，例如 `香港组`；再点一次「添加一跳」，选择落地节点或策略组，例如 `德国节点`。节点不在列表中时，可以按下文添加外部节点。
5. 检查「路径预览」。用「上移」「下移」调整顺序，用「移除」删除多余的一跳。两跳示例应显示为：

   ```text
   客户端 → 香港组 → 德国节点 → 目标
   ```

6. 在 **加入已有策略组（可选）** 中，勾选原规则使用的节点选择组，例如 `🚀 节点选择`。不要勾选链路自身用作前置或依赖的组，否则会形成循环。
7. 点击 **保存**。切换到所绑定的配置，在代理页面的 `🚀 节点选择` 中选中刚创建的链路；如果链路组内有多个出口，再选择需要的路径。

**保存链路不会自动改变原规则或切换当前选中的节点。** 未勾选「加入已有策略组」时，可在全局模式选择链路，或自行在覆写规则中引用生成的链路组名。名称冲突时会加上 `(2)` 等后缀，以代理页面实际显示的名称为准。

第一跳如果选择策略组，会跟随原组的实时选择；选择 Smart 组作为前置时，仍由 Smart 自动选路。切换前置节点应在原前置组中操作。后续策略组会展开为具体节点，例如「香港组 → 德国组」，德国组有 3 个节点时会生成 3 个出口选项，香港组的成员数量不会让两跳路径成倍增加。

### 2. 两个添加外部节点的入口

两处入口都提供 **手动添加** 和 **订阅链接**，支持的输入格式相同，区别在于节点保存在哪里。

| 入口 | 操作位置 | 保存与使用方式 |
| --- | --- | --- |
| 链路内添加 | 创建或编辑链路 → 添加一跳 → 窗口顶部的 **添加外部节点** | 导入后返回节点列表，再选择节点作为一跳；节点随当前链路保存，只加入链路生成的配置，不写回来源订阅文件。 |
| 配置内添加 | 配置 → 某个配置的编辑页 → 左下角的 **添加节点** | 节点追加到当前配置的 `proxies`；导入后还要点击编辑页右下角 **保存**。随后创建或编辑链路时即可在节点列表中选择。 |

只想给某条链路补充落地节点时，直接使用「添加外部节点」即可。希望节点写入当前配置，供该配置下的其他链路复用时，可以使用配置编辑页的「添加节点」。原配置开启订阅自动更新时，后续订阅更新可能覆盖手动添加的内容。

**导入节点不等于已把节点加入某一跳。** 在链路入口导入后，需要从返回的列表选中节点，并保存链路；在配置入口导入后，需要先保存配置，再到链路中选择节点。

### 3. 「手动添加」支持的格式

选择「手动添加」后，将内容粘贴到编辑器并保存。以下地址、端口、用户名和密码均为示例，使用时请替换为自己的真实节点参数。

#### 分享链接：每行一条

直接粘贴服务商或其他客户端复制的完整节点分享链接，例如 `ss://`（含 SS2022）、`vmess://`、`vless://`、`trojan://`、`hysteria2://` 等。多条链接分别放在不同行，保留完整参数；具体协议以当前打包内核的转换器支持为准。

下面是两条 HTTP / SOCKS5 分享链接的格式示例：

```text
http://demo-user:demo-pass@http.example.com:8080#HTTP-Exit
socks5://demo-user:demo-pass@socks.example.com:1080#SOCKS5-Exit
```

#### Mihomo YAML 节点

可以粘贴单个节点对象；添加多个节点时，使用标准 YAML 列表：

```yaml
- name: 德国落地
  type: socks5
  server: de.example.com
  port: 1080
  username: "demo-user"
  password: "demo-pass"
  udp: true
- name: HTTP 落地
  type: http
  server: http.example.com
  port: 8080
  username: "demo-user"
  password: "demo-pass"
```

没有认证的端点可以省略 `username` 和 `password`。其他协议使用对应的 Mihomo 字段，例如 SS 节点需要 `cipher` 和 `password`；SS2022 的密码须符合所选加密方式的密钥格式。

也支持从配置中复制的 `- {...}` 紧凑格式：

```yaml
- {name: 德国落地, type: socks5, server: de.example.com, port: 1080, username: "demo-user", password: "demo-pass"}
- {name: HTTP 落地, type: http, server: http.example.com, port: 8080}
```

#### JSON 节点对象或数组

单个 JSON 对象、多行大括号对象，以及标准 JSON 数组都可以使用。多节点数组示例：

```json
[
  {"name": "德国落地", "type": "socks5", "server": "de.example.com", "port": 1080, "username": "demo-user", "password": "demo-pass"},
  {"name": "HTTP 落地", "type": "http", "server": "http.example.com", "port": 8080}
]
```

还可粘贴带 `proxies:` 的完整 YAML 配置，或带 `"proxies"` 数组的 JSON 配置；只提取其中的节点。分享链接也可与大括号节点对象混合粘贴。

导入时会校验整批节点，任意一条无法识别或参数无效都会使整批失败，需要修正后再添加。同名节点会自动追加 `(2)` 等后缀；导入成功只表示格式和参数通过校验，仍需实际连接或测速确认服务端可用。

### 4. 「订阅链接」的用法

在任一添加入口选择 **订阅链接**，填入 HTTP(S) 订阅地址并点击「添加」，例如：

```text
https://subscription.example.com/nodes.yaml
```

支持包含实际 `proxies` 节点的 YAML / JSON、分享链接列表，以及 Base64 编码的链接订阅。此操作只导入节点，不导入订阅中的规则、策略组或 Provider 定义，**不会保存该链接供以后自动更新**。添加完成后，按所用入口继续选择一跳或保存配置。

如果订阅只包含远程 `proxy-providers` 定义，没有实际节点，不能通过此入口直接导入；可以先转换成包含节点的订阅，或将其作为正常配置导入、同步 Provider 后再创建链路。

### 5. 直接填写 HTTP(S) / SOCKS5 端点

对于这两类端点，也可以在 **添加一跳** 中选择 **本地 / 自定义 HTTP、SOCKS 端点**，直接填写表单：

- **名称**：用于辨认这一跳。
- **类型**：SOCKS5 或 HTTP(S)。
- **地址与端口**：地址只填主机名或 IP，例如 `de.example.com` 或 `127.0.0.1`；端口单独填写，范围为 1–65535。
- **用户名、密码**：需要认证时填写，否则留空。
- **TLS / HTTPS**：使用 HTTPS 代理时，在 HTTP(S) 类型下开启。

点击「添加」后，端点会直接成为当前链路的一跳。Android 上的 `127.0.0.1` 指手机本身；如果使用局域网中另一台设备上的代理，应填写那台设备的可达地址。

### 6. 保存、导出与常见提示

- **保存链路**：保留与来源配置的绑定，后续加载该配置时读取来源配置中的最新节点参数；直接导入的外部节点仍以链路中保存的内容为准。链路管理页可编辑、复制、启停或删除链路。
- **从链路创建本地配置**：生成包含链路的独立配置，保留原规则；创建后到配置页面切换使用。内置节点和链路副本是当时的快照，不再随来源订阅自动变化；HTTP Provider 仍保留自己的更新机制。
- **导出生成配置 YAML**：导出含链路的完整配置，可重新导入使用。管理页的「导入 / 导出」则处理链路库 JSON，适合与应用备份一起迁移，依赖原配置 ID。

每条链路最多 16 跳，默认最多 64 条路径，可调整为 16 / 64 / 256 / 1024；预览只展示前 20 条。路径过多时减少后续组的节点数量，或调整「最大路径数」。缺少落地 Provider 缓存时先同步资源，出现组循环时检查前置组和绑定组的关系。界面若提示 UDP、Reality、ShadowTLS 或已有 `dialer-proxy` 的兼容问题，应按实际节点条件检查，多跳可用性仍取决于各跳协议与服务端。

节点、导出配置和备份可能包含认证信息，请按普通订阅凭据保存。来源、实现结构及后续维护说明见 [代理链路维护说明](Proxy-Chains.md)。
